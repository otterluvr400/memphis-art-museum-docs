## Business Logic

<Steps>
  <Step title="Product Creation — Auto-fill from Category">
    When a `product.template` is created with a `categ_id` set, the `create()` override checks each of the five MAM fields. If the product's field is empty but the category has a value, the category value is copied to the product.
  </Step>
  <Step title="Category Push — Batch Update Products">
    The `action_push_mam_accounting_to_products` method on `product.category` searches all products in the category and writes all five MAM field values from the category to each product. This overwrites existing product values, including setting fields to empty if the category field is empty.
  </Step>
</Steps>

## Troubleshooting

- **Products not getting default MAM values on creation:** Ensure the product is created with a `categ_id` already set. The override only fires when `categ_id` is present in the create values.
- **Push to Products button missing:** Due to the XML ID collision described above, verify that `views/product_template_views.xml` is loaded (it contains the button definition that wins).
- **Push to Products clears product values:** This is by design — the button writes all five fields unconditionally, so empty category fields will clear non-empty product fields.

## Native Odoo 19 Comparison

### `product.template.create`

**Native Odoo 19:** Creates the product record with the values provided; no automatic inheritance of accounting fields from category.

**This module:** If `categ_id` is present and any MAM accounting field is empty on the product, the corresponding category default is copied in before calling `super().create()`.

**Why it matters:** Developers creating products via code (e.g., imports, API calls) should be aware that MAM fields may be silently populated from the category if left unset.

### `product.category` — MAM Accounting Push

**Native Odoo 19:** No batch-push mechanism for category-level accounting defaults.

**This module:** Adds `action_push_mam_accounting_to_products`, which overwrites all five MAM fields on every product in the category.

**Why it matters:** This is a destructive, one-way operation. There is no undo, and it affects all products in the category regardless of whether they already had custom values.
