## Business Logic

<Steps>
  <Step title="Card lifecycle tied to subscriptions">
    `res.partner._sync_membership_card()` looks for the partner's most recent active subscription (`is_subscription=True`, `subscription_state` in `3_progress`, `4_paused`, or `5_renewed`).
    - If an active subscription exists and no card exists, a card is created.
    - If the active state changes, `card.active` is toggled and `sync_state` reset to `pending`.
    - The latest qualifying subscription is stored in `subscription_id`.
  </Step>
  <Step title="Subscription state change hooks">
    `sale.order._compute_subscription_state` calls `super()`, compares old vs new state for subscription records, and triggers `_sync_membership_card()` on affected partners.
    `sale.order.write` also triggers sync if `subscription_state` is in the written values.
  </Step>
  <Step title="Daily cron: re-assert card state">
    `ir_cron_sync_membership_cards` runs daily, calling `_cron_sync_cards()` which finds all partners with subscriptions and re-syncs their cards.
  </Step>
  <Step title="Google Wallet push (placeholder)">
    `ir_cron_push_membership_cards` runs every 5 minutes, calling `_cron_push_pending()` which batches up to 50 pending cards and calls `_push_to_google_wallet()` per card. The implementation is currently a no-op placeholder logging debug output.
  </Step>
</Steps>

## Troubleshooting

- **Card not created after subscription purchase:** Verify `sale.order` has `is_subscription=True` and `subscription_state` enters one of the benefit-active states (`3_progress`, `4_paused`, `5_renewed`). The sync is triggered on compute and write hooks, but a daily cron also catches missed cases.
- **Google Wallet push not working:** `_push_to_google_wallet` is a placeholder. Wallet integration requires a future `google_wallet.py` implementation.
- **Duplicate card error:** The `partner_id` unique constraint prevents multiple cards per partner. If merging partners, handle card records first.

## Native Odoo 19 Comparison

### Subscription-based membership cards

**Native Odoo 19:** Odoo 19 does not ship a native Google Wallet or Apple Wallet membership card integration. Subscription products exist in `sale_subscription`, but wallet pass generation is custom.

**This module:** Adds a dedicated `mam.membership.card` model tied to subscription state, with planned Google Wallet push support.

**Why it matters:** The card state is fully derived from subscription state. Any bug in the sync logic or subscription state compute will incorrectly activate or deactivate membership cards.
