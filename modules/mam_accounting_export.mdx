## Business Logic

<Steps>
  <Step title="SQL View Construction">
    `mam.export.line` is a read-only SQL view unioning:
    - **Sale side:** confirmed `sale_order_line` records (state = `sale`, non-display lines) joined to `product_template` for MAM fields.
    - **POS side:** paid/done `pos_order_line` records joined to `product_template` for MAM fields.
    
    MAM fields are extracted from JSONB columns using `->> company_id::text` and cast to integer. Missing keys produce SQL NULL.
  </Step>
  <Step title="CSV Generation">
    `_build_csv(date_from, date_to)` searches `mam.export.line` within the date range, ordered by date. It writes a header row from `_CSV_COLUMNS`, then per line writes source, date, order ref, customer, product, qty, price, amount, and the five MAM field display names from the **current** product template (not historical).
  </Step>
  <Step title="Email Dispatch">
    `_send_export()` builds the CSV for the previous `window_days`, creates an `ir.attachment`, and sends a `mail.mail` with the attachment to `email_to`.
  </Step>
  <Step title="Scheduled Execution">
    `_cron_send_export()` (called daily by `ir.cron`) finds the singleton schedule. If `email_to` is set, it sends the export and recomputes `next_run`.
  </Step>
  <Step title="Manual Trigger">
    `action_send_now()` allows a user to send the export immediately from the schedule form.
  </Step>
</Steps>

## Troubleshooting

<AccordionGroup>
  <Accordion title="Export lines show current product MAM values, not historical">
    The SQL view joins to `product_template` at query time. If a product's GL Account, Project, etc. changed after the sale, the export reflects the current value, not the value at time of sale.
  </Accordion>
  <Accordion title="JSONB extraction returns NULL">
    Odoo 19 stores company-dependent fields as JSONB keyed by company ID. If the product was never saved for the order's company, or the key is missing, the export shows blank.
  </Accordion>
  <Accordion title="Cron runs but no email sent">
    `_cron_send_export()` silently skips if `email_to` is empty. Check the schedule record has a valid email address.
  </Accordion>
  <Accordion title="Duplicate IDs in view">
    Sale lines use `id * 2`, POS lines use `id * 2 + 1` to avoid collision in the union. This is safe unless the underlying tables exceed bigint range (extremely unlikely).
  </Accordion>
</AccordionGroup>

## Native Odoo 19 Comparison

### `product.template` company-dependent fields

**Native Odoo 19:** Stores company-dependent fields as JSONB on the table, keyed by company ID.

**This module:** The SQL view extracts these values with `->> company_id::text` and casts to integer. This bypasses the ORM's company-dependent resolution logic.

**Why it matters:** The export shows raw JSONB values. If the ORM would fall back to a default or parent company value, the export may differ from what the UI shows.

### Accounting export

**Native Odoo 19:** No built-in scheduled accounting export to CSV email.

**This module:** Custom SQL view + cron + mail integration provides a turnkey export pipeline.

**Why it matters:** This is a purely additive feature with no native equivalent to compare against.
