## Business Logic

### Folder lifecycle

<Steps>
  <Step title="Create folder">
    `website.folder.create()` calls `_ensure_loyalty_program()` to create or update a dedicated `loyalty.program` and a default percent discount rule. `program_type`, `applies_on`, `trigger`, and `active` are set only if the field/selection value exists.
  </Step>
  <Step title="Clone website group">
    `action_clone_website_group()` copies the source website's `website.group`, clones each website in the group into the new group, snapshots non-header views, ensures a `__design__homepage__{slug}` shell, then materializes the source website's header views and assets onto every destination website.
  </Step>
  <Step title="Activate folder">
    `action_activate()` simply sets `state` to `active`. The route `/&lt;slug&gt;` becomes resolvable once a matching active record exists.
  </Step>
  <Step title="Render folder homepage">
    `FolderingController.folder_home()` looks up the active folder by slug, stores `folder_slug` in session, finds `__design__homepage__{slug}`, forces request website resolution to that shell, and renders `website.homepage`.
  </Step>
  <Step title="Generate access codes">
    `action_generate_access_codes()` opens the wizard. `folder.access.code.wizard.action_generate()` creates one `loyalty.card` per code (with 9,999,999 points) and links each to a new `folder.access.code`.
  </Step>
</Steps>

### Routing and URL prefixing

- `ir.http._match()` strips the first URL segment when it matches an active folder slug, stores `folder_slug`/`folder_website`, and dispatches the remainder (`stripped_path`) to normal Odoo routing.
- `_add_folder_prefix()` rewrites relative URLs so generated links keep the `/slug` prefix. It skips absolute URLs, system roots (`/web`, `/static`, etc.), and URLs already prefixed.
- `_transactioning()` and `_dispatch()` intercept 3xx redirects and rewrite `Location` headers through the same prefix logic.
- `website.new_page()` prefixes new page URLs with `/p/` unless the first segment is an active folder slug.

### Header / SCSS relay from origin to folders

<Steps>
  <Step title="Detect origin change">
    `theme.utils.enable_view()` and `website.assets.make_scss_customization()` detect when the mutated website is an origin (non-folder) website via `_header_relay_origin_website()`.
  </Step>
  <Step title="Enqueue relay jobs">
    For recognized header-template keys, a `website.header.relay.queue` record is created (or updated) in `pending` state for every folder-group website.
  </Step>
  <Step title="Cron processes jobs">
    `ir_cron_header_template_relay` runs every minute and calls `_cron_process(limit=20)`, which disables all header-template option views on the target, enables the payload views, and writes the matching `header-template` SCSS variable.
  </Step>
  <Step title="Mirror option views to design shells">
    `_mirror_header_views_to_shells()` and `_mirror_scss_to_shells()` push origin header state and SCSS values to product-category design shells managed by `header_replacer`.
  </Step>
</Steps>

### Editor save routing

- `_save_oe_structure_hook()` reads the HTTP referer and, if it points to a folder route, forces the returned `website_id` to the folder base website or the `__design__homepage__{slug}` shell.
- `ir.ui.view.save()` bypasses the normal website save path when the referer resolves to a folder and the view being saved already belongs to the target website; it delegates directly to `html_editor.ir_ui_view.save` to avoid copy-on-write redirection.
- `save_embedded_field()` similarly swaps `request.website` to the folder target for embedded-field writes.

### Rendering website swap

- `ir.ui.view._render_template()` checks for an active design shell (from `header_replacer` context/request attributes) and otherwise swaps `request.env`/`request.website` to the folder base website for the duration of the render.
- Error templates (`http_routing.*`, `http_error*`) skip menu rebuild to avoid permission crashes during error rendering.

### Website shell provisioning

- `website.shell.create()` and `write()` call `_ensure_design_websites()`.
- The method looks up origin group `ref="1111"`, creates/updates `__design__{shell_name}` in the origin group, links or creates a matching `product.category` with `website_design_id`, and creates `__design__{slug}__{shell_name}` websites for every cloned folder, snapshotting origin views and materializing headers.

### Loyalty integration

- Each folder owns exactly one `loyalty.program`.
- The program is configured as `coupons`/`with_code`/`current` when those selection values exist, with one reward of type `discount`/mode `percent` and a single rule.
- Generated access codes create native `loyalty.card` records bound to that program and store the generated code in both `loyalty.card.code` and `folder.access.code.code`.

## Troubleshooting

- **Missing `header_replacer`:** The module depends on it in the manifest, but most provisioning logic (`website.shell`, `product.category._get_design_shell_websites`, `_init_design_websites`) assumes it is present and configured.
- **Origin group `ref="1111"` hard-coded:** `website.shell._ensure_design_websites()` searches `website.group` with `ref="1111"`. If that group does not exist or has no base website, shell provisioning silently logs a warning and exits.
- **No access rule for relay queue:** `website.header.relay.queue` lacks a CSV access row. Non-superuser admin inspection of queued jobs will be denied.
- **Duplicate `start_date` on `folder.discount`:** The second `start_date` declaration in `models/folder_addons.py` shadows the first. Verify which semantics are intended.
- **Hard-coded view IDs in spy logging:** `models/ir_ui_view.py` logs writes when `v.id in (1183, 2897)`. Those IDs are database-specific and will only trigger on the exact records created in the original database.
- **`folder_homepage` template unused by controller:** `FolderingController.folder_home()` normally renders `website.homepage` from the shell, not the `folder_homepage` QWeb template defined in views.
- **Race between cron and manual edits:** Header relay is asynchronous (1-minute cron). Editing the origin header and immediately viewing a folder may show stale state until the cron processes the queue.
- **`new_page` folder-slug collision:** `website.new_page()` preserves a URL if its first segment matches any active folder slug. Creating a page named after a folder slug will leave it unprefixed and may conflict with folder routing.
- **`product.category._init_design_websites` call at install:** `data/website_group_data.xml` calls `product.category._init_design_websites()`. That method is defined in `header_replacer`, not this module.

## Native Odoo 19 Comparison

### `ir.http._match`, `_pre_dispatch`, `_dispatch`, `_url_for`, `_transactioning`

**Native Odoo 19:** Routes are matched against the literal request path. URLs generated by `ir.http._url_for` and redirects are returned unchanged. No first-segment folder abstraction exists.

**This module:** The first URL segment is inspected for an active folder slug. When found, the remainder of the path is dispatched as if it were the real path, while `request` carries `folder_slug`, `folder_stripped_path`, and `folder_website`. Outgoing URLs and redirect `Location` headers are rewritten to keep the `/slug` prefix.

**Why it matters:** Public visitors see URLs like `/hyatt/shop`, but internally Odoo routes `/shop` against the folder's base website. Any third-party controller or hard-coded URL that bypasses `_url_for` may drop the folder prefix.

### `website.new_page()`

**Native Odoo 19:** Creates a page and menu under the current website with the requested URL.

**This module:** After calling `super()`, new page URLs are rewritten to `/p{original_url}` unless the URL starts with `/p/`, matches a system root, or matches an active folder slug.

**Why it matters:** The `/p/` prefix prevents collision with folder slugs, but it changes all public page URLs for every website, not only folder websites.

### `ir.ui.view._render_template()`

**Native Odoo 19:** Renders the requested template using the website in the current environment/request.

**This module:** If a folder website is active on the request, the environment and `request.website` are temporarily swapped to that folder website for the render, then restored in a `finally` block. Active design shells from `header_replacer` are skipped and instead trigger menu rebuild.

**Why it matters:** Template resolution, view copy-on-write, and menu rendering all depend on the active website. The swap must complete cleanly or `request.website` may be left pointing at a design shell.

### `ir.ui.view.save()` and `_save_oe_structure_hook()`

**Native Odoo 19:** Editor saves target the website-specific view derived from the current `request.website`/context.

**This module:** Saves inspect the HTTP referer to determine whether the request belongs to a folder route. If the target view already belongs to the resolved folder/design-shell website, the normal website save path is bypassed and `html_editor.ir_ui_view.save` is called directly to prevent copy-on-write redirection back to the origin view.

**Why it matters:** Without this bypass, saving a folder homepage could overwrite the source website's view or create a copy on the wrong website.

### `theme.utils.enable_view()` / `disable_view()`

**Native Odoo 19:** Toggles the named view on the current website only.

**This module:** Detects when the current website is an "origin" website and mirrors the resulting header selection to all folder-group websites through an async queue. Also mirrors header option active state to design shells maintained by `header_replacer`.

**Why it matters:** Header changes made in the origin editor are eventually pushed to every folder, keeping folder sites visually consistent without manual per-site edits.

### `website.assets.make_scss_customization()`

**Native Odoo 19:** Writes SCSS user values for the current website.

**This module:** After the native call, if the mutated website is an origin, the same SCSS customization is replayed onto every design shell and a header-relay job may be enqueued when the values contain `header-template`.

**Why it matters:** Theme/brand SCSS is kept in sync across shells; `skip_scss_mirror` context key can disable the mirror.

### Website group cloning

**Native Odoo 19:** Odoo's multi-website feature shares a database and lets each `website` have its own theme/views, but websites are independent records; there is no built-in "clone group with full view snapshot" operation.

**This module:** `website.folder.action_clone_website_group()` copies an entire group of websites, snapshots non-header views per website, materializes the source header view inheritance branch onto every destination, and creates a dedicated homepage shell. This produces self-contained websites where one `website_id` resolves the whole page.

**Why it matters:** The architecture trades storage duplication for rendering simplicity. Each folder has its own complete set of views, so changes must be relayed or re-cloned; they are not shared from a central template.
