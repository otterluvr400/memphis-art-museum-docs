# Mobile POS Relayout

Mobile POS Relayout (`mobile_pos_relayout`) changes the mobile Point of Sale UI and adds a full-screen client action that embeds the POS UI alongside the event barcode scanner and a customer/ticket search panel.

## Business Logic

### Mobile POS relayout

<Steps>
  <Step title="Cart button opens the left pane">
    `Navbar.prototype.onClickCartButton` sets `pos.mobile_pane = 'left'` and navigates to `ProductScreen` if not already there. This corresponds to the cart/order-lines pane on mobile.
  </Step>
  <Step title="Register button opens the right pane">
    `Navbar.prototype.onClickRegisterButton` ensures an order exists, navigates to `ProductScreen`, and sets `pos.mobile_pane = 'right'`. This corresponds to the product/register pane on mobile.
  </Step>
  <Step title="New order from burger menu">
    `Navbar.prototype.addNewOrder` creates a new order via `pos.addNewOrder()` and navigates to the order screen.
  </Step>
  <Step title="Review button replaced">
    On `ProductScreen`, the inherited template replaces the native review button with a `Customer` button. Pressing it triggers the standard partner selection flow (`pos.selectPartner()`).
  </Step>
</Steps>

### POS + Scanner wrapper

<Steps>
  <Step title="Client action loads">
    `PosScannerWrapper` is registered as `mobile_pos_relayout.pos_scanner_wrapper`. On `setup`, it fetches the first available `pos.config` record and stores its id.
  </Step>
  <Step title="POS iframe render">
    If a config exists, an iframe loads `/pos/ui/<config_id>`. If not, a "No POS Config Found" message is shown.
  </Step>
  <Step title="Bottom toggle buttons">
    The green user button opens the customer search panel. The primary toggle button switches between the POS iframe and the event scanner (`EventScanView`).
  </Step>
  <Step title="Customer search">
    `CustomerSearchPanel` performs a debounced (250 ms) `searchRead` on `res.partner` with a dynamic domain based on the query format (email, phone-like, or general). Selecting a partner loads their `event.registration` records and sorts them by state.
  </Step>
  <Step title="Ticket check-in / undo">
    Registrations in `open` or `draft` state can be marked `done` via `action_set_done`. Registrations already `done` can be reset to `open` via `action_confirm`.
  </Step>
</Steps>

## Native Odoo 19 Comparison

### `point_of_sale.Navbar` cart/register behavior

**Native Odoo 19:** The navbar uses `onClickRegister()` and the mobile `mobile_pane` toggle to switch between left (cart) and right (register) panes. The review button on `ProductScreen` opens the order/cart pane.

**This module:** Adds separate `onClickCartButton` and `onClickRegisterButton` handlers, explicitly sets `pos.mobile_pane` to `'left'` or `'right'`, and replaces the review button with a customer button.

**Why it matters:** The native two-pane toggle is split into explicit cart and register destinations. Developers updating the POS mobile state should update both the method and the pane assignment.

### `point_of_sale.ActionpadWidget` partner button

**Native Odoo 19:** The partner selection button is always visible in the action pad.

**This module:** Hides `SelectPartnerButton` when `ui.isSmall` is true, because partner selection is reached through the new customer button on the product screen.

**Why it matters:** On mobile, the action pad no longer provides the standard partner entry point. Any flow that relies on that button being present on small screens will fail.

### `point_of_sale.Navbar` burger menu

**Native Odoo 19:** The navbar dropdown menu does not include a "New Order" item.

**This module:** Adds a `DropdownItem` that calls `Navbar.prototype.addNewOrder()`.

**Why it matters:** A new convenience entry point is added to the existing menu; existing keyboard / screen-reader expectations may need testing.

### POS + event scanner wrapper

**Native Odoo 19:** The POS and event registration desk are separate apps/actions. There is no built-in action that embeds the POS UI inside an iframe next to the event barcode scanner.

**This module:** Creates a full-screen client action (`mobile_pos_relayout.pos_scanner_wrapper`) that embeds the POS UI in an iframe, overlays the event scanner, and provides a customer/ticket search panel.

**Why it matters:** This is a custom composite action that couples three independent subsystems. Changes to the event scanner action, the POS UI route, or iframe sandboxing may break the wrapper.

### Customer/ticket search panel

**Native Odoo 19:** Event registrations are managed through the event backend forms and the registration desk.

**This module:** Implements a lightweight frontend search panel that reads `res.partner`, fetches `event.registration` records by partner/email, and calls `action_set_done` / `action_confirm` directly from the UI.

**Why it matters:** This bypasses the normal event backend views and any validation or business logic that may be enforced there. It also sorts registrations locally using a hard-coded state priority (`open`, `draft`, `done`, `cancel`) rather than server-side ordering.
