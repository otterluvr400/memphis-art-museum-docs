## Business Logic

### LoginScreen feature toggle and GIF upload

<Steps>
  <Step title="Enable feature toggle">
    The `LoginScreen` template adds a checkbox below the Open Register button. Checking it calls `onToggleLoginFeature`, which opens `LoginFeaturePopup`.
  </Step>
  <Step title="Stage GIF files">
    `LoginFeaturePopup` lets the user select two GIF files (`memberFile`, `celebrationFile`). Previews are shown via `FileReader`. Confirming returns the staged files to `LoginScreen` via `onConfirm` callback.
  </Step>
  <Step title="Push GIFs after login">
    `LoginScreen.selectCashier` is patched to call `super()` first, then if staged GIFs exist and `pos.cashier` is set, `_pushStagedGifs` base64-encodes the files and writes them to `hr.employee` via `pos.data.call("hr.employee", "write", ...)`. Staged GIFs are cleared after the attempt.
  </Step>
  <Step title="Fallback write path">
    If `pos.data.call` fails, the code tries `pos.data.orm.write("hr.employee", [id], updates)` as a fallback.
  </Step>
</Steps>

<Warning>
  The `_pushStagedGifs` logic uses `this.pos.cashier?.employee_id?.id || this.pos.cashier?.id`.
  In `pos_hr` the cashier object should expose `employee_id`; without `pos_hr` the fallback is the
  cashier's own id, which may not be a valid `hr.employee` record. Confidence: **medium**.
</Warning>

### ProductScreen member GIF indicator

<Steps>
  <Step title="Track partner changes">
    A `useEffect` watches `this.currentOrder?.partner_id`. When a partner is selected and `memberGifUrl` is non-null, the member GIF is shown for 2.625 seconds (2625 ms).
  </Step>
  <Step title="Compute member GIF URL">
    `memberGifUrl` returns `/web/image/hr.employee/<employeeId>/x_gif_member_indicator` only when:
    - the order has a partner,
    - the partner has a non-default pricelist (`property_product_pricelist` differs from `pos.config.pricelist_id`),
    - a valid employee id can be derived from `pos.cashier`.
  </Step>
  <Step title="Render on customer button">
    The XML patch targets the customer button added by `mobile_pos_relayout` and inserts an `<img>` with `class="member-gif-corner"` at the top-right corner.
  </Step>
</Steps>

<Warning>
  The same "member = non-default pricelist" rule is used here and in `mobile_pos_relayout`'s
  `specialPricelist` getter. If the business definition of "member" changes, both modules
  need to be updated. Confidence: **medium**.
</Warning>

### ReceiptScreen celebration bubbles

<Steps>
  <Step title="Start on mount">
    `ReceiptScreen` is patched to start celebration on `onMounted`. It builds a fixed-position container appended to `document.body`.
  </Step>
  <Step title="Preload GIF">
    The employee's `x_gif_sale_celebration` is loaded via a new `Image`. On load, a single burst of 12–16 bubbles is spawned.
  </Step>
  <Step title="Spawn bubbles">
    Each bubble is a dynamically created `<img>` with randomized size, position, peak height, sway, drift, rotation, opacity, and duration. The `bubbleRise` CSS animation moves each bubble from the bottom to its peak, sways, then fades in place.
  </Step>
  <Step title="Stop celebration">
    After 3.75 seconds `_stopCelebration` fades the container and removes it on `onWillUnmount`.
  </Step>
</Steps>

### ShadowVisitor easter egg

`ShadowVisitor` is an ambient creature that appears rarely in the POS UI.

<Steps>
  <Step title="Schedule visits">
    Visits are persisted in `localStorage` under `pos_shadow_snail_schedule_v2`. Each two-week period has a 50% chance of one visit and an independent 10% chance of a second.
  </Step>
  <Step title="Build creature">
    `_build()` creates a DOM element with body, head, stalk eyes, shell, and arm. It is positioned on the left or right wall.
  </Step>
  <Step title="Behaviors">
    After peeking, it may leave, crawl up the wall, sit, or wave-then-leave. Pointer taps trigger `_speak()`, which displays a cryptic speech bubble.
  </Step>
  <Step title="Debug mode">
    Adding `?shadowdebug` to the URL makes visits rapid and continuous (ignores rarity).
  </Step>
</Steps>

<Warning>
  The shadow visitor uses `localStorage` directly, which may be unavailable in private browsing
  or restricted iframe contexts. The code catches storage errors and falls back to session-only
  behavior. Confidence: **medium**.
</Warning>

## Troubleshooting

- **GIF upload succeeds but GIFs do not appear:** Verify that `pos.cashier.employee_id.id` is populated (requires `pos_hr`) and that the user has write access to `hr.employee`.
- **Member GIF never shows:** The partner must have a pricelist different from the POS default. Check `property_product_pricelist` on the partner and `pricelist_id` on the POS config.
- **Member GIF does not render on the button:** The XPath targets the customer button added by `mobile_pos_relayout`. Verify `mobile_pos_relayout` is installed and its template still contains `btn-switchpane customer-button`.
- **Celebration bubbles do not appear:** The employee must have `x_gif_sale_celebration` set. Check the image URL `/web/image/hr.employee/<id>/x_gif_sale_celebration` loads correctly.
- **Shadow visitor appears too often or not at all:** Add `?shadowdebug` to bypass rarity. Check `localStorage` for `pos_shadow_snail_schedule_v2` to inspect the schedule.
- **Shadow visitor DOM elements leak:** The component cancels timers and removes elements in `destroy()`, but if the POS screen is torn down without calling `destroy()`, DOM nodes may remain.
- **Multiple modules patching the same screens:** `pos_qol_overrides` and `pos_stripe_tap` also patch `ProductScreen` and `ReceiptScreen`. Patch order and combined behavior may conflict.

<Warning>
  Name collision: `memberFile` and `celebrationFile` are local state keys with the same
  meaning in `LoginFeaturePopup` and `LoginScreen`. They are not model fields, but the
  naming is consistent across both components. Confidence: **high**.
</Warning>

## Native Odoo 19 Comparison

### `LoginScreen` customization

**Native Odoo 19:** The login screen allows cashier selection and PIN entry. It does not include a feature toggle for uploading employee GIFs.

**This module:** Adds a checkbox below the Open Register button that opens a popup for staging two GIFs, which are then written to `hr.employee` after successful login.

**Why it matters:** This is a non-standard UI customization that bypasses normal employee form editing. It assumes `pos.data.call` exposes `write` on `hr.employee` and that the cashier has the required permissions.

### `ProductScreen` customer button

**Native Odoo 19:** The product screen action pad has a partner button and a review button. There is no member-indicator GIF.

**This module:** Replaces the review button with a customer button (via `mobile_pos_relayout`) and adds a small animated GIF overlay when the selected partner has a non-default pricelist.

**Why it matters:** The visual indicator is tied to a specific business rule (non-default pricelist = member). If that rule changes, both the indicator and the pricelist display in `mobile_pos_relayout` must be updated together.

### `ReceiptScreen` celebration

**Native Odoo 19:** The receipt screen shows the order summary and payment details. There is no celebration animation.

**This module:** Appends a full-screen, fixed-position bubble container to `document.body` and animates the employee's sale-celebration GIF.

**Why it matters:** The overlay is appended outside the OWL render tree, so it does not participate in normal component lifecycle. Screen transitions or iframe sandboxing may leave stale DOM nodes.

### Employee GIF storage

**Native Odoo 19:** Employee records store photos and standard attachments.

**This module:** Adds two binary fields to `hr.employee` specifically for animated GIFs used in POS.

**Why it matters:** Large animated GIFs stored directly on `hr.employee` will be loaded into the POS image cache. Consider attachment storage and size limits.
