## Business Logic

<Steps>
  <Step title="Create a category">
    `create(vals_list)` is called. Each `vals["name"]` is trimmed and lowercased, then `super().create()` runs. After records are created, `_check_unique_within_parent` compares each new name against existing siblings under the same parent.
  </Step>
  <Step title="Write a category name">
    `write(vals)` is called. If `vals` contains `name`, the value is normalized. `super().write(vals)` runs. If the name changed, `_check_unique_within_parent` re-validates the projected names for all touched records.
  </Step>
  <Step title="Duplicate detection">
    `_check_unique_within_parent` builds a domain on `parent_id` and filters siblings whose normalized name matches. If any match exists, it raises a `ValidationError` with the conflicting record ID.
  </Step>
</Steps>

## Troubleshooting

<Warning>
  Name collision: `name` is a generic field on both extended models. The module always normalizes it, but downstream code that compares the raw value may see unexpected case changes. Confidence lowered to **medium**.
</Warning>

- **Category write blocked with "already exists"**: Two categories share the same parent and have the same normalized name. Rename one or change the parent.
- **Unexpected lowercase names**: This is by design. The mixin enforces `name = (name or "").strip().lower()` before any base logic runs.
- **Downstream syncs see normalized values only**: Because normalization happens before `super()`, hooks registered after this write (e.g., in `header_replacer`) receive the already-clean name.

## Native Odoo 19 Comparison

### `product.category` and `pos.category` name handling

**Native Odoo 19:** Base categories accept free-form `name` values and rely on optional `_sql_constraints` or user discipline. Duplicates are not prevented by default at the parent level.

**This module:** Names are always trimmed and lowercased, and duplicates under the same parent raise a `ValidationError` during `create` and `write`.

**Why it matters:** Consistent naming prevents accidental duplicate categories and ensures downstream integrations (e.g., header replacements, POS category mapping) receive predictable values.
